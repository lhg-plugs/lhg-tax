# lhg-tax-checklist：申报材料与时间节点

> 目标：把前面梳理出的收入项与扣除项，翻译成一份**"申报前要准备什么、何时办、在哪儿办"**
> 的 checklist，让用户照着打勾就行。
>
> 合规声明（本 skill 全程遵守）：
> **政策因地域与年份而异，更新快；本插件仅帮你整理扣除项清单与申报 checklist，
> 具体请咨询专业人士。**

## 1. 何时使用

- `/tax` 主流程走到最后一步 → 跑本 skill 收尾
- 用户问"汇算要准备哪些材料""什么时候办""在哪儿办"→ 直接跑本 skill
- 用户已在办申报、想对一遍材料齐不齐 → 跑本 skill 的材料核对版

## 2. 输入与输出

- **输入**：收入构成清单 + 扣除项清单（前面 skill 的产出；没有就先跑那两个）
- **输出**：`申报 checklist.md`（材料清单 + 时间节点 + 办理渠道 + 提交前核对）

## 3. 材料清单四类法

按下面四类组织材料，每类下列出来源、是否已备齐：

### 3.1 身份与基础信息

- 身份证明（办理时按官方渠道要求提供，本 skill 不登记证件号码）
- 本人银行账户信息（用于退税，按官方渠道要求填写，本 skill 不登记卡号）
- 任职受雇信息 / 扣缴义务人信息

### 3.2 收入凭证

- 工资薪金：个税 App 收入纳税明细、工资条
- 劳务报酬 / 稿酬 / 特许权使用费：合同、付款凭证、完税证明
- 经营所得：账簿、成本费用凭证（如适用）
- 其他所得：银行流水、交易记录

### 3.3 扣除凭证

对照扣除项清单逐项列：

- 专项附加扣除：每项的佐证材料（见 lhg-tax-deductions 第 3 节表格）
- 其他扣除：个人养老金缴费凭证、商业健康保险保单、公益捐赠票据等

### 3.4 申报辅助

- 上一年度申报记录（用于核对口径变化）
- 退税/补税相关的银行账户状态确认

### 3.5 材料纪律

1. **本 skill 只列清单，不收集原件**：身份证号、银行卡号等敏感信息一律不登记。
2. 每项材料标"已备 / 待备 / 不适用"，待备的写清"去哪里补"（如个税 App 哪个模块）。
3. 材料缺失不许脑补"应该没问题"——缺的就是缺的，列进待办。

## 4. 时间节点提醒

以下为公开办事指南中常见的时间框架（**具体以当年官方公告为准**，
本 skill 不记忆固定日期，用户每次使用时应以个税 App / 当地税务机关最新通知核对）：

1. **专项附加扣除年度确认期**：通常在每年年底（如 12 月）对次年扣除信息做确认/更新。
   有新增变化的务必更新，无变化的按官方指引一键确认。
2. **年度汇算办理期**：通常在次年上半年（如 3 月 1 日至 6 月 30 日）办理上一年度汇算。
3. **预约/错峰**：汇算初期可能需要预约，按官方通知操作。
4. **更正申报**：发现申报有误的，按官方渠道办理更正（注意撤销次数限制等规则）。

### 4.1 节点纪律

1. 写时间节点时必须加"以当年官方公告为准"或"请以当地最新政策为准"。
2. 不许写死"就是 3 月 1 日"这种绝对表述，除非同时写清来源与核对日期。
3. 给用户的提醒用"提前 X 天准备"的相对表述，而不是断言绝对日期。

## 5. 办理渠道

- **官方渠道**：个人所得税 App、自然人电子税务局、办税服务厅。
- 本插件**不代办、不代提交**：最终的填报、提交、退税申请、补税缴纳，
  一律由用户本人在官方渠道亲手完成。
- 遇到 App 操作问题 → 指引用户看官方帮助或咨询当地税务机关，
  不许编造操作路径。

## 6. 提交前核对（最后防线）

生成 checklist 末尾必须带"提交前核对"五问：

1. 收入项是否全？对照收入构成清单逐项打勾。
2. 扣除项是否全？对照扣除项清单逐项打勾。
3. 金额口径是否一致？税前/税后、年/月口径统一。
4. 银行账户是否有效？退税打款用。
5. 是否留存了本次申报的截图/回执？备查用。

## 7. 申报 checklist 模板

```markdown
# 申报 checklist（整理日期：____，未经核验）

## 一、材料清单
### 身份与基础信息
- [ ] ……
### 收入凭证
- [ ] ……
### 扣除凭证
- [ ] ……

## 二、时间节点（以当年官方公告为准）
- [ ] 专项附加扣除年度确认（通常每年年底）
- [ ] 年度汇算办理（通常次年上半年）
- [ ] ……

## 三、办理渠道
- 个人所得税 App / 自然人电子税务局 / 办税服务厅（由用户亲手办理）

## 四、提交前核对
- [ ] 收入项全了吗
- [ ] 扣除项全了吗
- [ ] 金额口径一致吗
- [ ] 银行账户有效吗
- [ ] 留存申报回执了吗

## 备注
- 本清单仅做信息整理，不构成税务建议，不代办申报。
- 政策因地域与年份而异，更新快；具体请咨询专业人士。
```

## 8. 反模式（不要这么做）

- ❌ 替用户在官方渠道点提交——提交是用户的法律行为，绝不代办
- ❌ 写死时间节点不加"以官方公告为准"——政策年年可能变
- ❌ 登记用户银行卡号、身份证号——隐私红线
- ❌ 编造 App 操作路径——不确定的就指引看官方帮助

## 9. 自检与反馈

每次执行完本 skill，做一次轻量自检：

1. 材料四类是否都覆盖了？→ 缺类补上。
2. 时间节点是否都加了"以官方公告为准"？→ 没加就补。
3. 是否出现了代办/代提交的表述？→ 删除，用户亲手办。
4. 是否登记了敏感证件号码？→ 立即删除，这是红线。

如发现本 skill 自身的方法论缺陷，按以下流程反馈：

- **标准冒烟用例**：用"工资 + 劳务报酬 + 两项扣除"的清单走一遍，
  检查材料四类是否齐全、时间节点是否有免责、提交前五问是否在。
- **一键提 issue**：确认问题后，以 `[QC] <一句话问题>` 为标题、
  正文写清"复现输入 → 错误输出 → 期望输出"，提交到 https://github.com/lhg-plugs/lhg-tax/issues。

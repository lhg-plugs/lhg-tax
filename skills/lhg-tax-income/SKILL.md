# lhg-tax-income：收入构成梳理

> 目标：把"我一年赚了多少、从哪儿赚的"这笔糊涂账，整理成一份**收入构成清单**，
> 让后续的扣除项梳理与申报 checklist 有据可依。
>
> 合规声明（本 skill 全程遵守）：
> **政策因地域与年份而异，更新快；本插件仅帮你整理扣除项清单与申报 checklist，
> 具体请咨询专业人士。**

## 1. 何时使用

- 用户说"帮我看看我的税""个税汇算要准备什么"→ 先跑本 skill，把收入构成理清楚再说
- 用户收入来源不止一份（工资 + 副业 + 理财等）→ 必须跑本 skill，防止漏项
- 用户只有单一工资收入且已有工资条 → 可用精简版（只做第 3 步的收入项登记）

## 2. 输入与输出

- **输入**：用户对自己收入来源的描述（可能零散、口语化，这是正常的）
- **输出**：一份 `收入构成清单.md`，包含：收入分类表、每项的金额口径、凭证归集状态、待确认事项

## 3. 第一步：收入类型分类

### 3.1 通用分类框架（名称为通用概念，具体口径以当地最新政策为准）

把用户的每笔收入先归入下面几类之一：

1. **工资薪金类**：月薪、年终奖、绩效、补贴、津贴
2. **劳务报酬类**：兼职、咨询费、讲课费、稿费之外的劳务收入
3. **稿酬 / 特许权使用费类**：出版稿酬、专利/版权许可收入
4. **经营所得类**：个体户、自由职业者的经营收入
5. **财产类所得**：房租、股权转让、利息股息红利等
6. **偶然所得类**：中奖、一次性奖励等

### 3.2 分类纪律

1. **一笔收入只进一类**：先按"钱从哪儿来"分，不确定的标"待确认"而不是硬塞。
2. **不评价、不建议**：只记录"是什么"，不说"怎么省税""怎么分摊"。
3. **金额只记用户说的**：用户没给数字就不编，记"未提供"。

## 4. 第二步：金额口径登记

### 4.1 登记三要素

每一项收入登记三个字段：

- **金额**：用户提供的税前/税后口径必须注明（如"月薪 15000 元（税前，用户提供）"）
- **期间**：是哪一年的、哪几个月的（如"2025 年 1–12 月"）
- **凭证**：工资条 / 银行流水 / 合同 / 发票 / 无凭证，照实记

### 4.2 金额书写规范

1. 数字必须带单位（元），不写裸数字。
2. 年收入与月收入不许混写，统一换算成年口径并注明换算过程。
3. 任何金额不许脑补：用户说"大概两万"就写"约 20000 元（用户口述估算）"。

## 5. 第三步：凭证归集

### 5.1 凭证清单模板

| 收入项 | 凭证类型 | 有无 | 备注 |
|---|---|---|---|
| 月薪 | 工资条 / 个税 App 收入明细 | □有 □无 | |
| 年终奖 | 发放通知 / 银行流水 | □有 □无 | |
| 劳务报酬 | 合同 / 付款方开具的凭证 | □有 □无 | |
| 房租 | 租赁合同 / 收款记录 | □有 □无 | |

### 5.2 凭证纪律

1. **不收集真实证件号码**：身份证号、银行卡号一律不登记，记"用户自行保管"。
2. 无凭证的收入项进"待确认"清单，不许默认"没问题"。
3. 电子凭证注明存放位置（哪个 App / 哪个文件夹），方便申报时找回。

## 6. 第四步：输出收入构成清单

清单模板：

```markdown
# 收入构成清单（2025 年度，用户提供，未经核验）

## 1. 收入分类表
| # | 类型 | 说明 | 金额（年口径） | 凭证状态 |
|---|---|---|---|---|
| 1 | 工资薪金类 | XX 公司月薪 | 180000 元（税前，用户提供） | 有（个税 App） |
| 2 | 劳务报酬类 | 兼职讲课 | 约 24000 元（用户口述估算） | 无 |

## 2. 待确认事项
- [ ] 劳务报酬是否为税前口径（待用户确认）
- [ ] 年终奖发放月份与金额（待用户提供）

## 3. 备注
- 金额均为用户提供，本清单不做真实性核验。
- 政策因地域与年份而异，更新快；本清单仅供整理参考，具体请咨询专业人士。
```

## 7. 反模式（不要这么做）

- ❌ 替用户"估算"他没说的收入——没说的就是没说，记"未提供"
- ❌ 给出"把年终奖拆开发可以省税"之类的筹划建议——这是红线，绝不碰
- ❌ 引用具体税率数字却不写来源与核对日期——凡引用政策数字必须同时写清来源与日期
- ❌ 登记用户的身份证号、银行卡号——隐私红线

## 8. 自检与反馈

每次执行完本 skill，做一次轻量自检：

1. 是否有收入项没写金额口径（税前/税后）？→ 补上或标"未提供"。
2. 是否有数字没写单位？→ 统一加"元"。
3. 是否出现了筹划建议的表述？→ 立即删除，这是红线。
4. 是否引用了政策数字但没写来源与日期？→ 补上，或删掉数字写"请以当地最新政策为准"。

如发现本 skill 自身的方法论缺陷，按以下流程反馈：

- **标准冒烟用例**：用"月薪 1.5 万 + 兼职讲课年入约 2.4 万"走一遍本 skill，
  检查分类是否正确、金额口径是否注明、待确认事项是否列出、是否零筹划建议。
- **一键提 issue**：确认问题后，以 `[QC] <一句话问题>` 为标题、
  正文写清"复现输入 → 错误输出 → 期望输出"，提交到 https://github.com/lhg-plugs/lhg-tax/issues。

## 附录：常见收入情形速查

| 情形 | 归类建议 | 凭证提示 |
|---|---|---|
| 每月固定工资 | 工资薪金类 | 个税 App 收入明细 |
| 年终奖 / 年终绩效 | 工资薪金类（单独列一行，注明发放月份） | 发放通知、银行流水 |
| 周末兼职讲课费 | 劳务报酬类 | 合同、付款方凭证 |
| 公众号/出书稿费 | 稿酬类 | 出版合同、结算单 |
| 专利授权给公司用 | 特许权使用费类 | 许可合同 |
| 开小店/接单收入 | 经营所得类 | 账簿、收支记录 |
| 出租房租金 | 财产租赁类 | 租赁合同、收款记录 |
| 卖股票/基金的收益 | 财产转让类（只记"有发生"，金额按用户提供） | 券商对账单 |
| 公司发的过节奖金 | 工资薪金类（并入当月或单独列，注明） | 工资条 |

注意：上表只是"归类建议"，不涉及税额计算；凡涉及"怎么申报更划算"的问题，
一律回答"请咨询专业人士"，不展开。

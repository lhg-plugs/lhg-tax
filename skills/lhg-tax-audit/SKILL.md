# lhg-tax-audit：整理成果自查

> 目标：对收入构成清单、扣除项清单、申报 checklist 做一次**确定性自查**，
> 用脚本先扫一遍硬伤，再人工过一遍脚本扫不到的。
>
> 合规声明（本 skill 全程遵守）：
> **政策因地域与年份而异，更新快；本插件仅帮你整理扣除项清单与申报 checklist，
> 具体请咨询专业人士。**

## 1. 何时使用

- `/tax:audit` 命令调用 → 全程按本 skill 执行
- 每次给用户交付清单文档之前 → 至少跑一遍脚本自查
- 用户说"帮我检查下这份清单有没有问题"→ 跑本 skill

## 2. 输入与输出

- **输入**：待自查的清单文档目录（含收入/扣除/checklist 任一或全部）
- **输出**：分级自查报告（blocker / warning / nit）+ 修复建议，结论"通过 / 不通过"

## 3. 第一步：跑确定性脚本

```bash
python3 <插件目录>/scripts/audit/tax_audit.py --target <清单目录> --format text
```

脚本规则覆盖（全部原创规则，零第三方依赖）：

| 类别 | 规则方向 | 说明 |
|---|---|---|
| 结构 | TAX-STRUCT | 清单文档是否含收入/扣除/材料/时间节点四要素 |
| 完整性 | TAX-CMP | 专项附加扣除七项是否全覆盖 |
| 红线 | TAX-RED | 是否出现筹划建议表述（节税建议/合理避税等） |
| 红线 | TAX-LEAK | 是否出现身份证号/银行卡号等敏感信息 |
| 红线 | TAX-TODO | 是否残留 TODO/待补充等未完成标记 |
| 政策 | TAX-DATE | 政策数字是否带来源与核对日期 |
| 政策 | TAX-NUM | 金额是否有单位、格式是否规范 |
| 合规 | TAX-DISC | 是否含免责声明（仅供参考/请咨询专业人士） |
| 材料 | TAX-MAT | 申报材料四类是否齐全 |
| 时间 | TAX-TIME | 关键时间节点是否提及并加免责 |

分级定义：

- **blocker**：必须修。含筹划建议、敏感信息、缺免责声明、TODO 残留、七项缺项。
- **warning**：修或写豁免理由。政策数字缺来源日期、金额格式问题、材料缺类。
- **nit**：顺手修。标题层级、格式小毛病。

## 4. 第二步：分级与修复

1. blocker：逐条修，修一条用脚本复查一条。
2. 修不掉的（如用户坚持要写筹划建议）→ **拒绝执行该条**，
   向用户说明红线，不许为过审改规则。
3. warning：修掉或写豁免理由（+有效期）；nit：顺手修。
4. **硬规则**：有 blocker 就说"通过"→ 不许；为清零改脚本规则或阈值 → 这是作弊，不许。

## 5. 第三步：人工评审（脚本扫不到的）

1. **口径一致性**：同一笔收入在收入清单和 checklist 里的金额、口径是否一致。
2. **适用性复核**：扣除项的"适用/不适用"判定有没有明显硬伤
   （如无子女却勾了子女教育——标出来让用户确认，不替用户改）。
3. **时效性**：文档里的政策表述有没有过期风险，过期风险高的加"请核对最新政策"批注。
4. **隐私复核**：全文再扫一遍，确认无真实证件号、卡号、详细住址。

## 6. 自查报告模板

```markdown
# 自查报告（日期：____）

## 脚本结果
- blocker：N 项（清单：……）
- warning：N 项（清单：……）
- nit：N 项（清单：……）

## 人工评审
- 口径一致性：通过 / 问题：……
- 适用性复核：通过 / 待用户确认：……
- 时效性：通过 / 需加批注：……
- 隐私复核：通过 / 问题：……

## 结论
通过 / 不通过（原因：……）

## 备注
- 本自查只检查整理质量，不构成税务建议。
- 政策因地域与年份而异，更新快；具体请咨询专业人士。
```

## 7. 反模式（不要这么做）

- ❌ 有 blocker 还说通过——这是失职
- ❌ 为清零改规则——这是作弊
- ❌ 替用户改"适用/不适用"判定——标出来让用户自己确认
- ❌ 把自查报告写成税务建议——报告只谈整理质量

## 8. 自检与反馈

每次执行完本 skill，做一次轻量自检：

1. 脚本是否跑了？→ 没跑不算自查完。
2. blocker 是否清零或明确拒绝？→ 有一处含糊都不许说通过。
3. 人工评审四项是否都过了？→ 缺项补上。
4. 报告结论是否只有"通过/不通过"？→ 不许写"基本通过"。

如发现本 skill 自身的方法论缺陷，按以下流程反馈：

- **标准冒烟用例**：用 fixtures/tax-bad 跑脚本，确认红线规则全部命中；
  用 fixtures/tax-good 跑脚本，确认零 blocker。
- **一键提 issue**：确认问题后，以 `[QC] <一句话问题>` 为标题、
  正文写清"复现输入 → 错误输出 → 期望输出"，提交到 https://github.com/lhg-plugs/lhg-tax/issues。
